# Decisions log

Add a line for every dependency or architecture decision. Format: ID — decision — reason.

- D-001 — KWin 6 is the compositor; we do not write one. — Mature, fast, avoids years of compositor work.
- D-002 — Base is Ubuntu 26.04 LTS. — Ships KWin 6 / Qt 6, supported until 2029.
- D-003 — UI is Qt 6 Qt Quick + cxx-qt, Rust backend. — Native Wayland/layer-shell support, strong tooling, Rust for logic.
- D-004 — Taskbar window list comes from a KWin JS script over D-Bus. — Plasma window protocol is restricted; script is simpler and also enables tiling later.
- D-005 — Development is nested KWin inside GNOME in a UTM VM; real session tested only at milestones. — Safe, fast iteration.
- D-006 — Plasma Shell, Kirigami and org.kde.* QML are never used. — The shell must be fully our own product.
- D-007 — Our code is MIT; dependencies must be permissive (see docs/LICENSING.md); Qt is the documented LGPL exception (dynamic linking). — Matches the preference for MIT/BSD while keeping the best UI stack.
- D-008 — Quality gate is `scripts/verify.sh` locally and in CI; PRs only, signed commits, Conventional Commits. — Enterprise-grade process, even for a solo project.
- D-009 — Services are separate systemd user units with hardening; UI and daemon talk only via versioned D-Bus interfaces. — Security, modularity, crash isolation.
- D-010 — Performance claims only from measured baselines against Plasma on the same hardware (docs/PERFORMANCE.md). — KWin is shared, so wins come from shell weight, startup, latency, visuals.
- D-011 — Lock screen must use a real session-lock mechanism, never an overlay window. — Security.
- D-012 — Presentation is fully separated into swappable style packs (tokens, skins, surfaces, KWin decoration/effects, assets); archetypes are described by behavior with neutral names. — Easy future styles, no third-party names/assets.
- D-013 — Scope order: complete desktop environment first, distro ISO/installer only after 1.0; v1 ships as .deb packages installable on Ubuntu 26.04. — Focus; a DE is the hard, valuable part.
- D-014 — Namespace `org.kynexos` for D-Bus names, app IDs and desktop IDs; copyright holder "Kynex Project contributors". — Fixed identifiers from the start so nothing needs renaming.
- D-015 — Style packs are code (QML): loaded only from system/user styles dirs, validated, restricted imports, unsigned-pack warning. — Security.
- D-016 — Pin `cxx-qt` to exact version `0.10.0` with `cxx-qt-build` and `cxx-qt-lib`. — Pinned stable integration with Qt 6 on Ubuntu 26.04.
- D-017 — Use `zbus` 6.x for IPC to avoid unmaintained dependencies on `zvariant` and `zbus_names`. — Security and long-term maintenance.
- D-018 — `LayerSurface` is a C++ `QQuickWindow` subclass delegating to `LayerShellQt::Window` for Wayland layer-shell protocol integration. — Minimal C++ shim keeping presentation logic cleanly in QML.
- D-019 — Internal design docs (`docs/`), dev templates (`templates/`), and setup prompts (`SETUP.md`) are excluded via `.gitignore` from the public repository. — Privacy and security for public repository.
- D-020 — Internal agent prompt files (`AGENTS.md`, `.agents/`) are excluded via `.gitignore` from the public repository. — Enterprise best practice, presenting a clean production repository.
- D-021 — Kynex Shell DE code is licensed under GPL-3.0-or-later with a Contributor License Agreement granting sole relicensing authority to Saif Mnasri; third-party dependencies strictly remain MIT/BSD/Apache preferred. — Prevents third-party companies from creating proprietary/closed-source forks while preserving the founder's right to relicense to MIT or closed-source in the future.
- D-022 — QML module URIs are Kynex.Shell (core types) and Kynex.Style (design tokens singleton and style API), strictly aligning with docs/BRAND.md and deprecating org.kynexos.core. — Standardized brand hierarchy and static validation via qmldir/qmltypes.
- D-023 — [Superseded by D-030] GitHub Actions CI ran on ubuntu-24.04 host runners prior to containerized execution. — Superseded by D-030 container: ubuntu:26.04 workflow.
- D-024 — Root daemon D-Bus interface is org.kynexos.Daemon.Core1 adhering to org.kynexos.Daemon.<Name>1 standard established in docs/DBUS_API.md. — Consistency with modular sub-service interface naming conventions.
- D-025 — Power management is implemented via org.kynexos.Daemon.Power1 in kynex-daemon delegating to UPower DisplayDevice (/org/freedesktop/UPower/devices/DisplayDevice) via asynchronous signal-driven zbus proxy, consumed by PowerModel in kynex-shell. — Avoids direct external service coupling in UI, ensures non-polling zero-wakeup architecture, and guarantees graceful fallback (present=false) when UPower or battery hardware is absent.
- D-026 — Battery low warning threshold is encapsulated in `kynex-common::BATTERY_LOW_PERCENTAGE` (20.0%) and exposed via `PowerModel.low` property in Rust. — Keeps QML presentation-only and strictly avoids hardcoding logic or numbers in QML.
- D-027 — Style token linting strictly rejects all numeric literals in `styles/**/*.qml` except 0 and 1 across properties, expressions, comparisons, and ternaries. — Enforces design tokens architecture and catches evade attempts.
- D-028 — Runtime thread bounding: `kynex-daemon` runs on a single-threaded Tokio runtime (`current_thread`), `kynex-shell` runs on a bounded 1-worker Tokio runtime, and `zbus` is configured with `features = ["tokio"]` avoiding extraneous `zruntime` background executor threads. — Minimizes idle memory footprint and reduces context switches.
- D-029 — Systemd user unit sandboxing: Ineffective directives requiring unprivileged user namespaces or elevated privileges (`PrivateNetwork=yes`, `ProtectHostname=yes`, `ProtectSystem=strict`, `ProtectHome=read-only`, `PrivateTmp=yes`, `IPAddressDeny=any`, `ProtectKernelTunables=yes`, `ProtectControlGroups=yes`, `ProtectProc=invisible`, `ProcSubset=pid`) are removed from the packaged user unit (`systemd/kynex-daemon.service`) because unprivileged user managers on Ubuntu 26.04 lack `CAP_SYS_ADMIN`/`CAP_NET_ADMIN`/`CAP_BPF` and Ubuntu restricts unprivileged user namespaces (`kernel.apparmor_restrict_unprivileged_userns = 1`), causing degraded warnings in the journal ('proceeding without', 'ignoring namespace setup') or failing to isolate mount/network namespaces. The packaged unit retains ONLY empirically proven effective directives (`NoNewPrivileges=yes`, `RestrictAddressFamilies=AF_UNIX`, `SystemCallFilter=@system-service`, `SystemCallArchitectures=native`, `RestrictRealtime=yes`, `RestrictNamespaces=yes`, `RestrictSUIDSGID=yes`, `MemoryDenyWriteExecute=yes`, `LockPersonality=yes`, `KeyringMode=private`, `UMask=0077`), verified by `scripts/test-systemd-unit.sh` with a 100% clean user journal. — Honest sandboxing without degraded journal warnings or unverified security claims.
- D-030 — GitHub Actions CI runs the verification gate inside an official `container: ubuntu:26.04` environment on an `ubuntu-24.04` runner host (and runs secret-scan on the runner host). — Guarantees complete environmental fidelity with our Ubuntu 26.04 LTS target, compiling against native Qt 6.10, KWin 6.6, LayerShellQt, and Wayland protocols while caching cargo binaries and Rust build artifacts.
- D-031 — Network connectivity is implemented via `org.kynexos.Daemon.Network1` in `kynex-daemon` delegating to NetworkManager (`org.freedesktop.NetworkManager`) via asynchronous signal-driven `zbus` proxies, consumed by `NetworkModel` in `kynex-shell`. Attacker-controlled SSID strings are strictly sanitized in Rust (capped at 32 bytes, stripped of control characters and Unicode bidi override characters U+202A-202E, U+2066-2069, invalid UTF-8 bytes filtered). Weak signal threshold (<= 25%) is encapsulated in `kynex-common::NETWORK_WEAK_SIGNAL_PERCENTAGE` and exposed as `NetworkModel.weak` in Rust. — Guarantees privacy (never exposes IP addresses, MAC, or BSSID), security against terminal/UI spoofing, and keeps QML strictly presentation-only.
- D-032 — Base UI controls are encapsulated in the QML module `Kynex.Controls` (`KynexButton`, `KynexSwitch`, `KynexSlider`, `KynexTooltip`, `KynexListItem`). All components are token-driven via `Kynex.Style` tokens (colors, radii, spacing, motion, opacity, focus ring), have zero numeric literals except 0 and 1, provide comprehensive state handling (hover, pressed, focus, disabled), enforce visible focus rings and keyboard navigation (Tab/Shift-Tab, Space/Return, Arrow keys), implement full accessibility metadata (`Accessible.role`, `Accessible.name`, `Accessible.focusable`, action triggers), support RTL bidirectional layout via `LayoutMirroring`, and support runtime style skin overrides via `styles/<id>/components/`. — Guarantees consistent system ergonomics, accessibility compliance, clean separation between design system tokens and presentation controls, and zero style hardcoding in core.
- D-033 — Volume (PipeWire/WirePlumber) and Bluetooth (BlueZ) indicators are moved from Phase 2 to Phase 5 (Quick Settings). In modern desktop UX (and Kynex Shell's dock/panel architecture), volume and Bluetooth interactions belong to interactive quick settings flyouts/sliders rather than standalone read-only panel text indicators. Phase 2 exits cleanly with complete base controls (`Kynex.Controls`), visual regression test harness, hardened user daemon sandboxing, and battery + network status indicators. — Consolidates interactive controls in their natural UI surface and prevents premature panel clutter.
- D-034 — Window feed contract separation: A private feeder interface `org.kynexos.Daemon.WindowsFeed1` is dedicated exclusively to the KWin feeder script, accepting flat primitive arguments (`Reset()`, `Upsert(id s, title s, appId s, minimized b, active b)`, `Remove(id s)`, `SetActive(id s)`) because KWin's built-in `callDBus()` binding cannot serialize structs or maps. A public read-only interface `org.kynexos.Daemon.Windows1` serves the shell and session clients with a structured list (`List() -> a(sssbb)`) and real-time signals (`Added`, `Changed`, `Removed`, `ActiveChanged`). — Bypasses KWin scripting limitations while providing a clean, strongly-typed API for shell models.
- D-035 — Feeder authentication and hostile window sanitization: The private feeder interface enforces a layered, fail-closed authentication policy via pure decision function `evaluate_feeder_auth`: 1) caller UID matches daemon session UID; 2) caller unique bus name matches current `GetNameOwner("org.kde.KWin")` on every call (tracked continuously via `NameOwnerChanged`); 3) if `/proc/<pid>/exe` is readable it must match EXACTLY `/usr/bin/kwin_wayland` (no filename or suffix fallbacks). If `/proc/<pid>/exe` is unreadable due to kernel non-dumpable file capabilities (`cap_sys_nice=ep`), the daemon relies on layers 1+2 and logs once; any other inspection error rejects. Residual risk: a rogue same-UID process starting before KWin could claim `org.kde.KWin`, causing DoS to KWin, though spoofing feed data still requires elevated/root capabilities to simulate capability-restricted `/proc` state. All window titles are treated as untrusted attacker input and sanitized in pure Rust: capped at 256 bytes sliced strictly on valid UTF-8 character boundaries, stripping ASCII controls (C0/C1) and Unicode bidi override/isolate characters (U+202A-202E, U+2066-2069). Window IDs are restricted to <= 64 chars of `[0-9A-Fa-f{}-]`. Window appIds are restricted to <= 128 chars of `[A-Za-z0-9._-]`. Capacity is hard-bounded to 512 windows total with a 200 calls/s sliding-window rate limit and dropped-call counter. — Prevents feeder spoofing, terminal escape injection, UI spoofing, bidi inversion attacks, and D-Bus flooding DoS.
- D-036 — Taskbar presentation architecture and storm coalescing: Taskbar buttons in `styles/default/Shell.qml` are rendered using a horizontal, viewport-clipped `ListView` bounded between panel margins rather than an unbounded `Repeater`, preventing unbounded delegate allocation when hundreds of windows exist. In `kynex-shell`, `WindowListModel` coalesces rapid signal bursts in background Tokio with a 25 ms debounce interval, preventing Qt Quick scenegraph churn and keeping memory overhead under 1 MB even during 512-window storms. — Eliminates UI freezing and unbounded memory consumption.
- D-037 — Daemon Landlock self-sandboxing is scheduled for Phase 8: Rather than relying on unprivileged user namespace directives in systemd which trigger degraded warnings on Ubuntu 26.04, `kynex-daemon` will self-sandbox using the Linux Landlock LSM to enforce filesystem access restrictions without namespace unshare penalties. — Documented in Phase 8 roadmap.
- D-038 — Window action mechanism via short-lived KWin scripts: KWin 6.6 exposes no native D-Bus methods on `/KWin` or `/org/kde/KWin` for activating, minimizing, restoring, or closing specific windows by internal ID. Window actions (`Activate`, `Minimize`, `Restore`, `Close`) on `org.kynexos.Daemon.Windows1` are executed by `kynex-daemon` delegating to KWin's `org.kde.kwin.Scripting` interface (`loadScript`, `/Scripting/Script<N>.run`, `unloadScript`). Each action script is synthesized from a static CONSTANT template with only a pre-validated, existing window UUID (regex-checked, existing in daemon state) inserted. The script is written to a private `0700` temporary directory as a `0600` file with an unpredictable UUID filename, loaded into KWin, executed immediately, unloaded via D-Bus, and unlinked, preventing TOCTOU. Daemon rate-limits actions to 20 calls/s per client, rejects unknown or non-existent IDs, and runs with zero `unwrap()`, zero `expect()`, and zero `unsafe`. — Provides reliable window actions on KWin 6 without patching KWin or inventing fragile D-Bus hacks.
- D-039 — Applications indexing and secure process launching: Applications are indexed from `$XDG_DATA_DIRS/applications` via `kynex-apps-index` conforming strictly to the Freedesktop.org Desktop Entry Specification v1.5, enforcing hard security bounds (file <= 64 KiB, line <= 4 KiB, groups <= 50, keys <= 200, regular files only, symlink cycle protection). Exec parsing expands spec field codes without invoking any shell interpreter (`/bin/sh`), preventing shell command injection. Applications are launched via direct `process_group(0)` detached execution with active child exit reaping via asynchronous Tokio tasks bounded by a concurrency semaphore (`MAX_CONCURRENT_WAITERS = 64`), ensuring processes survive daemon restarts and avoid defunct zombies while the daemon runs (ADR-008 Option B). Process execution uses a sanitized environment allowlist (`HOME`, `PATH`, `XDG_*`, `WAYLAND_DISPLAY`, `DBUS_SESSION_BUS_ADDRESS`, `LANG`, `LC_*`, `DISPLAY`), null standard I/O, same-UID authentication, 5 calls/s daemon-wide rate limiting, and logs only the application ID. Directory changes are tracked via inotify (`notify` crate) blocking on `rx.recv()` with a 200 ms debounce window starting only after the first filesystem event, emitting a single `Changed()` signal per burst without polling. Ranked search uses an in-house matcher under 200 lines scoring exact, prefix, word-start, and subsequence matches with deterministic ordering. — Guarantees security against hostile desktop files, prevents process orphan/zombie issues, avoids third-party search dependencies, and eliminates polling wakeups.
- D-040 — Stage K2 Audit Remediations (AUD-K-01 through AUD-K-06): 1) Captured ambient Tokio runtime handle prior to spawning the background inotify watcher thread, eliminating runtime panics on filesystem events, and installed a process-aborting panic hook in daemon `main()` to trigger systemd auto-restarts on unexpected thread death. 2) Replaced zombie process accumulation with bounded asynchronous child waiter tasks (`MAX_CONCURRENT_WAITERS = 64`) awaiting `child.wait()`, strictly complying with `#![forbid(unsafe_code)]` while preserving process survival across daemon restarts and subreaper reparenting. 3) Restructured watcher loop to block indefinitely on `rx.recv()` when idle, entering the 200 ms debounce window only after the first filesystem event, achieving zero idle context switches (0.00 cswch/s) and zero futex wakeups. 4) Added QML tests for RTL `LayoutMirroring` and design token bindings, killing all non-equivalent mutants (98.9% kill ratio) with only 2 verified equivalent mutants remaining. 5) Enforced a daemon-wide sliding window rate limit of 5 launches/s across all D-Bus connections under the user's UID. 6) Re-measured release daemon PSS honestly under realistic (300 apps: 9.28 MB post-query) and stress (5,000 apps: 15.38 MB post-query) workloads, updating documentation and formally retracting inaccurate audit claims. — Restores zero-polling guarantees, eliminates process leaks, hardens against rate limit bypasses, and upholds audit integrity.
- D-041 — Stage L Waiter Bug Fix & Process Supervision Correction: The child waiter semaphore (`MAX_CONCURRENT_WAITERS = 64`) inside the waiter task (`let _permit = semaphore.acquire_owned().await; child.wait().await;`) held permits for the entire lifetime of launched applications. Once 64 apps were running, subsequent launches acquired no waiter, accumulating defunct zombie processes without bound when later apps exited before earlier ones. Fixed by removing the semaphore in favor of unbounded Tokio waiter tasks bounded by the 5/s daemon launch rate limiter, tracking active children via an atomic gauge logged at debug level. Verified with 200 concurrent children exiting with 0 zombies within 1 s across 20 test runs, and 10 s real-limiter runs. Corrected ADR-008 and documented test limitations in `docs/work/stage-k2-report.md`.
- D-042 — Launcher Model and Asynchronous Query Architecture: Shell `LauncherModel` is implemented as a CXX-Qt `QAbstractListModel` acting as an asynchronous D-Bus client of `org.kynexos.Daemon.Apps1`. Search input is trimmed and capped at 128 characters, result sets are clamped to <= 50 entries, and queries are tracked via a monotonically increasing sequence number in pure Rust (`SearchTracker`) ensuring latest-wins semantics (stale out-of-order replies cannot overwrite newer results). Untrusted metadata (`name`, `generic_name`, `comment`) is sanitized in pure Rust (stripping ASCII controls 0x00-0x1F, 0x7F and Unicode bidi overrides/isolates U+202A-202E, U+2066-2069) and rendered with `textFormat: Text.PlainText` across all QML surfaces. Selection navigation wraps circularly, and enter launches via `Apps1.Launch`.
- D-043 — Launcher Overlay Surface and LayerShell Focus Integration: `styles/default/Launcher.qml` implements a centered overlay using `LayerSurface` positioned on the `Overlay` layer (`LayerShellQt::Window::LayerOverlay`) with exclusive keyboard interactivity (`LayerShellQt::Window::KeyboardInteractivityExclusive`) appropriate for text entry. Lazy-loaded via a QML `Loader` on first trigger to avoid cold startup overhead, the launcher responds to global shortcut `Meta+Space` registered via KWin scripting (`ShellFeed1.LauncherShortcut`), Esc to dismiss, and click-outside backdrop dismissal. Focus transfers automatically to `KynexSearchField` upon mapping.
- D-044 — Stage L2 Audit Remediations & Technical Honesty (AUD-L-01 through AUD-L-05): 1) Extracted pure-Rust logic into `kynex-shell-core` without Qt dependencies, achieving 97.86% line coverage. 2) Replaced synthetic latency measurements with shell internal monotonic timestamps (`LauncherToggleRequested` to `frameSwapped`), measuring warm open p50 3.48 ms / p95 4.31 ms and on-demand cold open p50 67.27 ms / p95 74.37 ms in VM llvmpipe; evaluated idle pre-warming in an experimental script only (`dev/bench/measure_prewarmed_latency.py`, achieving p95 57.84 ms at +0.73 MB PSS cost) and deliberately did not ship it in production code, preserving on-demand lazy loading and zero idle wakeups (decision deferred to Phase 8 on real hardware); split budgets into cold and warm in `budgets.toml`. 3) Resolved CI visual regression by bundling Inter static TTFs (OFL-1.1) in `assets/fonts/` with minimal fontconfig and `QT_QPA_FONTDIR` isolation, and pinning `actions/upload-artifact` to full SHA on failure. 4) Eliminated all 10 `qmllint` compiler shadowing warnings in `Launcher.qml` via typed property bindings. 5) Killed all 5 auditor mutants (M04-M08) with 10 unit tests in `tst_launcher.qml`, achieving 98.7% mutation kill ratio (223/226 killed, 3 verified equivalents documented in `tests/mutation-equivalents.md`). 6) Clarified shortcut honesty: nested KWin runs with `--no-global-shortcuts` (real keys untested until Phase 8); experimentally verified against KWin 6.6 that legacy `kwinrc [ModifierOnlyShortcuts]` is absent from KWin binaries/libraries and proposed KGlobalAccel `Meta` mapping in ADR-009. — Restores rigorous technical integrity, eliminates fake timings, closes test gaps, and establishes deterministic visual testing.
- D-045 — Icon lookup in UI-free crate `kynex-icons` with asynchronous C++ `QQuickAsyncImageProvider` and deterministic theme selection: Icon resolution follows Freedesktop Icon Theme Spec v0.13 in pure Rust library crate `kynex-icons` in-process within `kynex-shell` rather than `kynex-daemon` over D-Bus IPC (ADR-010). Loading runs asynchronously via `QQuickAsyncImageProvider` in worker thread pool, preventing UI thread stalls and avoiding D-Bus roundtrips or daemon PSS bloat. Deterministic theme selection reads `~/.config/kynex/config.toml` (`[icons].theme`), falling back to distribution system `default` / standard `hicolor` with zero third-party trademarks hardcoded; missing icons fall back cleanly to letter badges. Decoders enforce 16 MB allocation limit, pre-decode header size validation, and safe SVG parsing. — High rendering performance, zero UI stalls, strict trademark neutrality, and hardened image decoding.
- D-046 — Desktop Notifications Specification v1.2 implementation, internal Notifications1 contract, and core logic crate separation: `kynex-daemon` implements `org.freedesktop.Notifications` v1.2 with non-replacing well-known name acquisition (`DO_NOT_QUEUE`, never replacing existing owners; disables standard endpoint gracefully if already owned) and exposes `org.kynexos.Daemon.Notifications1` for `kynex-shell` (ADR-011). Advertises `body` and `actions` capabilities while strictly omitting `body-markup` (all markup stripped to plain text) and `persistence` (in-memory ring buffer of 200 items, not written to disk across restarts). All state machine logic, token-bucket rate limiting (10 burst, 2/s sustained), payload bounds, image-data validation (<= 256x256, 8-bit, 3-4 ch, checked arithmetic), bidi/control filtering, and event-driven deadline timers are isolated into UI-free, D-Bus-free pure Rust crate `kynex-notifications` (`#![forbid(unsafe_code)]`, GPL-3.0-or-later). — Robust spec compliance, zero-polling expiry, zero crash/replace conflicts with foreign daemons, and strict defense-in-depth against untrusted notification payloads.
- D-047 — Desktop Notifications Specification Conformance — `replaces_id` Allocation Semantics and `CloseNotification` Error Handling (Stage N2 Remediation, AUD-N-03 & AUD-N-04): 1) Authoritative specification conformance: Adhered to the exact text of Desktop Notifications Spec v1.2 §4.1 ("If replaces_id is not 0, the returned value is the same value as replaces_id") by returning `replaces_id` directly for non-zero IDs when not owned by another active client, while strictly verifying that ID-squatting attempts by client B cannot mutate or hijack client A's active notifications (returning `SenderMismatch`), and making the sequential ID generator skip in-use IDs. 2) Adhered to Spec v1.2 §4.2 ("If the notification no longer exists, an empty D-BUS Error message is sent back") by sending an empty D-Bus error reply (`zbus::fdo::Error::InvalidArgs(String::new())`) on non-existent or foreign `CloseNotification` calls, formally refuting the auditor's claim that `CloseNotification` should return silently. 3) Enforced per-sender token-bucket rate limiting uniformly across all `Notify` invocations regardless of whether `replaces_id` is 0 or non-zero. (ADR-012) — Full specification compliance, zero ID collisions, and robust sender isolation.
- D-048 — StatusNotifierWatcher implementation, internal Tray1 contract, and kynex-tray core crate: `kynex-daemon` implements `org.kde.StatusNotifierWatcher` and `org.freedesktop.StatusNotifierWatcher` with non-replacement `DO_NOT_QUEUE` bus acquisition on `/StatusNotifierWatcher` and exposes `org.kynexos.Daemon.Tray1` for `kynex-shell` (ADR-013). All registry management (keyed by unique bus name and object path), sender verification (client cannot register someone else's service), per-sender (<= 4) and total (<= 64) limits, removal on NameOwnerChanged / explicit unregister, status enum mapping, hostile string sanitization (bidi/controls dropped, markup stripped, length caps), IconPixmap checked arithmetic validation (<= 64x64, data == w*h*4, total <= 64 KiB, ARGB to RGBA byte conversion), icon name filtering (kynex-icons rules only, absolute paths rejected), 2s async property read timeout, signal-driven refresh (10/s rate limit), and 0 unwrap/expect/unsafe are isolated in UI-free, D-Bus-free pure Rust crate `kynex-tray` (GPL-3.0-or-later). Context menus delegate directly to the item's ContextMenu method; dbusmenu is out of scope and deferred. — Robust spec compliance, zero-polling, crash isolation, and defense-in-depth against untrusted tray payloads.
